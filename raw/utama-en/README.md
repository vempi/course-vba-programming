## Learning design

Each module is designed for **2 credits or 100 minutes**. The learning sequence is intentionally simple:

```text
see a case → predict → learn the concept → watch a demonstration
           → practise → test the result → explain it in your own words
```

Each meeting produces one small, demonstrable artefact and ends with three high-impact questions:

1. **Predict:** determine the result before running the formula or program.
2. **Practise/fix:** create or repair an artefact.
3. **Explain:** justify the result instead of memorising syntax.

## Typical 100-minute pattern

| Stage | Typical duration | Activity |
|---|---:|---|
| Orientation | 5–10 min | case, objective, and initial prediction |
| Core concept | 15–25 min | short explanation and concrete example |
| Demonstration | 15–20 min | instructor models the complete process |
| Practice | 30–40 min | students create and modify the example |
| Exercise and reflection | 10–15 min | three questions, checking, and explanation |

Sections marked **Extension** are not required during class. The instructor may distribute a workbook containing table headings and starter data so class time is spent on algorithms and code.

## Required software

- Microsoft Excel desktop with VBA;
- workbooks saved as `.xlsm`;
- AutoCAD with a VBA environment only for the optional demonstration; and
- a browser for reading the Markdown materials on GitHub.

> Enable macros only in files from trusted sources. Keep a backup before running a macro that changes many cells or drawing objects.

## Conventions

- Every standard VBA module starts with `Option Explicit`.
- Variable names communicate meaning and units, such as `length_m`.
- Excel examples use English function names. Your Excel installation may use commas or semicolons as argument separators.
- While editing a formula, **F4** cycles through relative and absolute references. **F5** opens the *Go To* dialog.
- Every program result is checked against a simple case or manual calculation.
